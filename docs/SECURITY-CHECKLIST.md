# Security Checklist — SIM Casting JBTB (Pre-Launch)

> **Status: campuran** — dicatat 21 Agu 2026 sebagai BACKLOG penuh (proposal, belum coding). Diverifikasi ulang 28 Agu 2026 terhadap kode Sprint 1-6 (`DEV-NOTES.md` Session 1) — cek langsung ke `app/Models`, `app/Http/Controllers`, `app/Http/Middleware/CheckRole.php`, `routes/web.php`, `config/session.php`. Kolom **Status** di bawah hasil verifikasi kode nyata, bukan cuma klaim dev notes.

Sumber: checklist umum keamanan aplikasi (20 poin), dipetakan ke konteks Laravel + kebutuhan spesifik JBTB.

| # | Item | Status | Kenapa relevan di sistem ini | Cara implementasi di Laravel |
|---|---|---|---|---|
| 1 | Hide API Keys | DONE (arsitektur) | Token shared-secret ke `whatsapp-service/` (self-hosted, bukan Fonnte/Wablas — lihat `TECH-STACK.md`), SMTP Gmail, dsb | Terverifikasi: `.env`/`.env.backup`/`.env.production` masuk `.gitignore`; `app/Services/WhatsAppService.php` akses token lewat `config('services.whatsapp.token')`, tidak ada `env()` langsung di kode aplikasi |
| 2 | Purge Git Secrets | BACKLOG | Repo `extras` udah lumayan lama jalan — worth di-scan riwayatnya | Scan history repo pakai `git-secrets`/`trufflehog`; kalau ketemu secret ke-commit, **rotate** kredensialnya, jangan cuma hapus commit-nya |
| 3 | Jangan expose kredensial DB ke client-side | DONE (arsitektur) | Semua akses data extras/fee/margin harus lewat backend | Semua query lewat Laravel backend (Eloquent/API), tidak ada akses DB langsung dari JS/frontend — terverifikasi, tidak ada endpoint yang expose koneksi DB ke client |
| 4 | Role-Level Security | DONE | 7 role dengan visibilitas data beda-beda (tembok anti-poaching di `CLAUDE.md` §5) | Terverifikasi: `CheckRole` middleware (`app/Http/Middleware/CheckRole.php`) + `role:...` per route group di `routes/web.php` (super_admin, admin_default+sub-role, extras, casting_director). Bukan Policy/Gate formal, tapi middleware per grup route dicek nyata |
| 5 | Encrypt Sensitive Data | DONE | KTP/NIK, foto/video profil, rekening | Terverifikasi: `ExtrasProfile::casts()` — `nik`, `nama_asli`, `rekening` di-cast `'encrypted'`; foto/video/signature disimpan via `Storage::disk('local')` (private, bukan public). **`users.nomor_wa` (RF-37, 29 Agu 2026) sengaja TIDAK di-encrypt** — beda kelas sensitivitas dari NIK/rekening (setara `email`/`name` di tabel yang sama), dan perlu tetap queryable buat validasi duplikat nomor nanti; proteksinya lewat `#[Hidden]` (nggak ke-serialize ke tembok visibilitas CD, `CLAUDE.md` §5), bukan encryption. **RF-04 blind index (29 Agu 2026, fix cycle):** `nik` tetap `encrypted` (IV random, tidak bisa di-`WHERE`) — duplicate lookup lewat kolom teknis terpisah `nik_hash` (`extras_profiles`, string(64) unique, HMAC-SHA256). Key HMAC-nya **`NIK_HASH_KEY`**, terpisah dari `APP_KEY` (`config('app.nik_hash_key')`) — kalau key ini pernah dirotasi, semua `nik` di `extras_profiles` yang sudah ada harus didekripsi & di-hash ulang pakai key baru SEBELUM key lama dibuang, kalau tidak deteksi duplikat diam-diam berhenti bekerja untuk record lama (hash lama tidak match hash dari key baru walau NIK sama) |
| 6 | Enforce server-side auth | DONE | Role nggak boleh cuma dipercaya dari session client | Terverifikasi: `auth` + `role:` middleware di route groups, plus authorization manual di controller (`pastikanBolehLihat()` di `ContractController`, `pastikanBolehLihatMedia()` di `Extras\ProfileController`) — bukan trust dari frontend state |
| 7 | Lock record access | DONE (manual, bukan Policy) | Extras cuma boleh liat profil/riwayat sendiri; CD cuma liat kandidat yang diajukan ke dia | Belum pakai Laravel Policy `view`/`viewAny` formal, tapi scoping manual per method (`pastikanBolehLihat()`/`pastikanBolehLihatMedia()`) sudah menegakkan pemilik/role yang berhak — terverifikasi di `ContractController`, `Extras\ProfileController` |
| 8 | Block field tampering | DONE | Extras nggak boleh bisa self-set Grade atau fee sendiri lewat request yang dimanipulasi | Terverifikasi: `ExtrasProfile` pakai atribut `#[Fillable([...])]` (pola Laravel 13), kolom `status`/`cancel_count` sengaja TIDAK masuk daftar — cuma berubah lewat `recordCancellation()`. Validasi field per role masih inline `$request->validate()`, belum Form Request class terpisah |
| 9 | Secure session cookies | SEBAGIAN (30 Agu 2026) | Standar tapi wajib dicek pas deploy production (HTTPS) | `.env.example` sudah punya `SESSION_SECURE_COOKIE=false` dengan komentar "set true di production". **Masih manual**: belum ada guard kode yang otomatis paksa `true` di production — Fakrul WAJIB set env var ini eksplisit saat deploy, jangan asumsi default aman |
| 10 | Hash password | DONE (default) | Sudah RNF-03 di Bab 3 | Default Laravel (`bcrypt`), belum diubah — no action tambahan diperlukan |
| 11 | Rate limit login/apply | DONE (30 Agu 2026) | Cegah brute force login & spam apply lowongan | Terverifikasi: `throttle:5,1` (5x/menit) di `routes/web.php` untuk `/login`, `/register`, `/register/casting-director`, `/forgot-password`, `extras.projects.apply`, `extras.kontrak.simpan-ktp`. Test `test_login_kena_rate_limit_pada_percobaan_keenam` membuktikan percobaan ke-6 dapat 429 |
| 12 | Bot protection | BACKLOG | Registrasi Extras terbuka ke publik | Belum ada CAPTCHA di form register & login |
| 13 | Parameterize queries | DONE (default Eloquent) | Cegah SQL injection | Terverifikasi: tidak ditemukan `DB::raw`/`whereRaw` di `app/` — semua query lewat Eloquent (auto-parameterized) |
| 14 | Validate all input | SEBAGIAN | Semua form (profil, proyek casting, nego fee, upload) | Terverifikasi: `$request->validate()` dipakai luas (26 pemanggilan di 14 controller), tapi masih inline per method, belum pakai Form Request class terpisah |
| 15 | Escape user content | DONE (default Blade) | Bio/portofolio Extras yang ditampilkan ke Admin/CD | Terverifikasi: tidak ditemukan `{!! !!}` di `resources/views` — semua output lewat `{{ }}` auto-escape |
| 16 | Restrict file uploads | DONE | Foto/video profil, scan KTP, bukti transfer — semua upload dari publik | Terverifikasi: validasi `mimes:`/`max:` di controller upload (foto/video/bukti transfer), disimpan `Storage::disk('local')` (private, bukan public root) |
| 17 | Trim API responses | SEBAGIAN | Jangan sampai response API balikin field NIK/rekening/margin ke role yang nggak berhak | Belum ada API Resource/transformer formal, tapi query ke view CD sudah select kolom terbatas (mis. `extras:id,alias,foto_profil_path,video_profil_path` di `Cd\ReviewController`) — field sensitif tidak dikirim, meski caranya manual per query bukan transformer reusable |
| 18 | Security headers | DONE (30 Agu 2026) | Standar hardening | Terverifikasi: `app/Http/Middleware/SecurityHeaders.php` (global, `bootstrap/app.php`) set `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, dan CSP yang mengizinkan cuma host yang benar-benar dipakai (Google Fonts, jsDelivr Tabler Icons/Chart.js). Test `test_response_punya_security_headers`. Belum ada HSTS header terpisah — cek lagi kalau HTTPS production sudah aktif |
| 19 | Force HTTPS | DONE (arsitektur, 30 Agu 2026) | Wajib karena ada data KTP/rekening yang dikirim lewat form | `AppServiceProvider::boot()` — `URL::forceScheme('https')` kalau `app()->isProduction()`, tidak aktif di local/testing (diverifikasi: full suite tetap 71 passed tanpa gangguan). HSTS header (`Strict-Transport-Security`) belum ditambahkan — pertimbangkan sekalian kalau nambah HSTS ke `SecurityHeaders` nanti |
| 20 | Scan dependencies | BACKLOG | Composer & npm package bisa punya vulnerability | Belum ada `composer audit` rutin atau Dependabot aktif |
